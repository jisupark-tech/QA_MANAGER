# 레드마인 버그 리포트 형식 가이드

> 실제 레드마인 스크린샷(image.png ~ image-6.png)을 분석하여 역추출한 형식입니다.

---

## 1. 이슈 헤더 구조

```
QA #[번호] [상태 배지]

[이슈/개선] 제목 — 간결하고 구체적으로 (현상 중심)

작성자이(가) N일/N달 전에 추가함. N일/N달 전에 수정됨.
```

### 헤더 필드 레이아웃

| 좌측 | 값 | 우측 | 값 |
|------|---|------|---|
| **상태** | 신규/진행중/작업완료/QA완료/재발생/재현불가/의견/현상태진행/보류/추후확인 | **시작시간** | YYYY/MM/DD |
| **우선순위** | 긴급/높음/중간/낮음/보통 | **완료기한** | YYYY/MM/DD (선택) |
| **담당자** | 이름 (링크) | **진척도** | 0~100% (프로그레스바) |
| **목표버전** | N차 | **추정시간** | (선택) |

---

## 2. 제목 작성 규칙

### 접두사
- **`[이슈]`** — 결함, 버그, 오류
- **`[개선]`** — 편의성 향상, 기능 제안, UX 개선

### 제목 패턴 (실제 사례 기반)
```
[이슈] {위치}에서 {동작} 시 {증상}
[개선] {대상}을 {개선 방향}하도록 {요청}
```

#### 실제 제목 예시
- `[이슈] 슬롯 이동하여 무기 선택 후 이전 슬롯으로 복귀하여 강화 2회 이상 시 무기 변경됨`
- `[이슈] 방어구 슬롯 강화 페이지에서 경지 변경 시 주문서 순서 뒤섞여 잇음`
- `[이슈] 무술 출파 후 다른 페이지로 이동했다 복귀하여 같은 버튼 선택 시 출파 니 노출`
- `[개선] 캐릭터가 최고 레벨일 경우 경험치가 딱 떨어지지 않으면 경험치 Bar가 100%가 되지 않음`
- `[개선] 제작 시 제작 가능한 최대치로 수량 정해지도록 개선 건의`
- `[개선] 추가 필요: 설정 – 메인` (기능 요청)

## 3. 설명(본문) 작성 형식

### 표준 구조
```
[참고 영상/URL] (선택)
↳ YouTube URL 또는 스크린샷

[재현 경로]
1. (시작 위치/화면)
2. (동작 1)
3. (동작 2)
4. (결함 발생 시점)

[현재 결과]
• 실제 발생하는 현상 설명
  (부가 설명이 있으면 들여쓰기로 추가)

[기대 결과]
• 기획 의도에 따른 정상 동작 설명
```

### 추가 항목 (해당 시에만)
```
[비고] (선택)
• 재현율, 특정 조건, 간헐적 발생 시 시도/재현 횟수
• 특정 디바이스에서만 발생 시 디바이스/OS 정보
• 에러 코드가 있을 경우 에러 로그 전문 첨부
```

## 4. 실제 버그 리포트 샘플

### 샘플 A — 이슈 (중간 우선순위)

```
QA #6934

[이슈] 슬롯 이동하여 무기 선택 후 이전 슬롯으로 복귀하여 강화 2회 이상 시 무기 변경됨

상태: 신규          시작시간: 2025/11/28
우선순위: 중간      담당자: (개발자 이름)
목표버전: 2차

───────────────────────────────
설명

↗ https://youtu.be/O3I5gGxa47Y

[재현 경로]
1. 슬롯 A에서 무기 장착
2. 슬롯 B로 이동하여 임의의 무기 선택 (장착 X)
3. 슬롯 A로 복귀
4. 장착돼있는 무기 강화

[현재 결과]
• 강화 도중 무기가 변경됩니다.
  해당 무기를 보유하지 않은 경우에도 장착이 가능합니다.
  (무기 장착 시 장착 효과가 0으로 반영됨)

[기대 결과]
• 강화 도중 무기가 변경되지 않아야 합니다.
```

```
QA #(번호)

[이슈] 방어구 슬롯 강화 페이지에서 경지 변경 시 주문서 순서 뒤섞여 잇음

상태: 신규          시작시간: 2025/12/02
우선순위: 낮음      담당자: (개발자 이름)
목표버전: 2차

───────────────────────────────
설명

↗ https://youtu.be/8ByVK8FYITs

[재현 경로]
1. 방어구 > 슬롯 강화 페이지 진입
2. 경지 A 선택
3. 주문서 선택
4. 경지 B 선택
5. 주문서 팝업 진입

[현재 결과]
• 주문서의 순서가 뒤섞여 있습니다.
  (스크린샷 첨부)

[기대 결과]
• 주문서의 순서가 오름차순으로 나열돼야 합니다.
```

### 샘플 C — 개선 (데이터 테이블 관련)

```
QA #6861

[개선] 캐릭터가 최고 레벨일 경우 경험치가 딱 떨어지지 않으면 경험치 Bar가 100%가 되지 않음

상태: 신규          시작시간: 2025/11/18
우선순위: 보통      담당자: (개발자 이름)
목표버전: (해당 차수)

───────────────────────────────
설명

조건:
1. 몬스터 1마리 처치 시 exp 5 받기
2. 레벨업 시 필요한 경험치는 다음과 같음

(엑셀 데이터 테이블 첨부 — Index, Exp, Level_Point 컬럼)

참고:
↗ https://youtu.be/y122L942_4

발전 사항:
캐릭터가 최고 레벨일 경우
몬스터를 처치 시 획득하는 경험치가 레벨업에 필요한 경험치와 나눗셈으로 딱 떨어지지 않으면
경험치 Bar가 100%로 될 수 없게 됩니다.
```

## 5. 레드마인 필드 값 정의

### 상태 흐름
```
신규 → 재현불가 / 의견 / 진행중 / 현상태진행
         ↓
      작업완료 / 보류
         ↓
      QA완료 / 재발생 / 추후확인
```

### 우선순위
| 값 | 아이콘 | 정의 | 출시 가능 여부 |
|----|--------|------|---------------|
| **긴급** | ⬆⬆ | 플레이 불가능 (APP Crash, 강제 종료) | 불가 - 반드시 수정 |
| **높음** | ⬆ | 특정 기능 사용 불가, 결제 관련 모든 결함 | 불가 - 반드시 수정 |
| **중간** | ⬇ | 플레이에 문제 없는 UI 결함, Max Level 결함 | 조건부 - 기획자와 논의 |
| **낮음** | ⬇⬇ | 편의성 개선, 로그 누락, 기획과 미세 상이 | 가능 |
| **보통** | — | 개선 사항, 기능 요청 | 가능 |

### 목표버전
- `N차` 형식 (1차, 2차, 3차...) — 개발 스프린트/마일스톤 단위

### 진척도
- `0%` → 등록됨 (신규)
- `100%` → QA 완료

## 6. 댓글/히스토리 패턴

레드마인에서 상태 변경 시 자동으로 `Property changes`가 기록됨:

```
김도빈이(가) N일 전에 수정
  · 담당자: (없음) → 개발자A
  · 상태: 신규 → 진행중

개발자A이(가) N일 전에 수정
  · 상태: 진행중 → 작업완료
  (댓글) 수정되었습니다.

김도빈이(가) N일 전에 수정
  · 상태: 작업완료 → QA완료
  (댓글) 확인 완료했습니다.
```

재발생 시:
```
김도빈이(가) N일 전에 수정
  · 상태: 작업완료 → 재발생
  (댓글) 1. 은 수정되었으나
         1. 은 수정되지 않았습니다.
```

## 7. 첨부 파일 패턴

| 유형 | 용도 | 형식 |
|------|------|------|
| **YouTube 영상** | 재현 경로 영상 촬영 | URL 링크 |
| **인게임 스크린샷** | 현재 결과 시각적 증거 | PNG |
| **데이터 테이블** | 계산식/수치 관련 이슈 | 엑셀 스크린샷 또는 표 |
| **에러 로그** | Unity 에러 발생 시 | 텍스트 (Console 로그 전문) |
